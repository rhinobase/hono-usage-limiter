## Long-term Knowledge

### Architecture

<!-- lore:019f033c-4bd6-7865-8bd8-9af861df9ac8 -->
* **hono-credit package structure: dual CJS/ESM with /memory subpath export**: Package renamed from \`hono-credit\` to \`hono-usage-limiter\`, version \`0.1.0\`, repo \`rhinobase/hono-usage-limiter\`. Main entrypoint: \`src/index.ts\` (exports types, CreditManager, middleware). Separate entrypoint \`src/memory.ts\` for \`/memory\` subpath export — dual CJS/ESM: \`dist/memory.{js,cjs,d.ts,d.cts}\`. Built with pkgroll. Credit cost formulas: Transcribe = \`ceil(audioDurationSeconds)\` credits; Post-process = \`ceil(inputTokens / 100)\` credits. Rolling window bucket model with optimistic gate (allows slightly negative balance).

<!-- lore:019f033c-4bd0-7db2-b646-09ffb156cbfa -->
* **hono-credit: DB-agnostic credit management via CreditStore adapter interface**: hono-usage-limiter (formerly hono-credit) is Hono-focused but database-agnostic — users implement the \`CreditStore\` interface with 5 methods (\`getBucket\`, \`createBucket\`, \`updateBucket\`, \`deduct\`, \`getLedger\`). No SQL migrations are shipped. A \`MemoryStore\` is included for testing (exported via \`/memory\` subpath). The library injects a single \`CreditManager\` object onto Hono context as \`c.get('credit')\` via \`creditManager()\` middleware. Handlers control all logic by calling \`credit.check()\`, \`credit.deduct()\`, \`credit.getBalance()\`, \`credit.getHistory()\`, \`credit.reset()\`, \`credit.provision()\`. Middleware only injects — it does not auto-deduct.

### Gotcha

<!-- lore:019f033c-4bd4-7d47-83d4-bd15de15ebf4 -->
* **MemoryStore getLedger: sort by insertion index, not timestamp**: Trap: sorting ledger entries by \`created\_at\` timestamp (Date.now()) looks correct for newest-first ordering. Fix: entries created in rapid succession (e.g. in tests) get identical timestamps, making the sort unstable and tests flaky. \`MemoryStore.getLedger\` must sort by reversed insertion index instead of timestamp. This was a confirmed bug in \`src/memory.ts\` caught by the test \`MemoryStore > should return ledger entries newest first\`.
